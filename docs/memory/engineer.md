Give a new component class its CSS in `BaseLayout.astro`'s `<style is:global>` block, not in the page's own `.astro` file, when the markup is created by a DOM module (`*-dom.ts`) rather than written in the template. Astro only attaches its scoped `data-astro-cid-*` attribute to elements present in the template at compile time, so a class a script creates at runtime never matches a scoped selector and silently gets no styling at all — it renders with browser defaults, unit tests pass (they check for the class/testid, not computed style), and only a real render shows the gap. #82's round 1 review caught this: several home-feed/restaurant-page classes had never had a CSS rule anywhere, so cards and rows fell back to unstyled defaults despite every acceptance test being green.

When a DOM module sets an `<img>`'s `width`/`height` as HTML attributes (to reserve layout space and avoid shift), also give that class `width: 100%; height: auto` in CSS — the attributes alone fix the image at that intrinsic pixel size regardless of its container, which overflows a narrow viewport the moment the container is smaller than the attribute value. Unit tests don't lay out CSS so they stay green; #82's round 2 review caught it as a sideways-scrolling page only a real render showed.

When prose in an `.astro` template wraps onto a new source line right before an inline element (`<code>`, `<strong>`), keep the trailing space on the same line as that element rather than after the line break — Astro's HTML compression collapses a newline between a text node and the inline element that follows it, so "kept for\n<strong>up to one hour</strong>" renders as the glued "forup to one hour". A test that only checks each phrase is present somewhere in the built text (`toContain('up to one hour')`) still passes glued, because the surrounding words it globs together aren't part of that assertion — the test has to assert the adjacent words together. #83's round 1 review found four of these on `/about` that the existing built-output test had missed.

The engineer role's `gh` access in this environment covers only `gh issue`/`gh pr` subcommands (matching its granted `mcp__github__*` tools) — `gh run`, `gh api` and `gh repo` are refused outright, even for a read like fetching a failed job's log. When a workflow-triggered check (like `photos`'s `fetch` job) fails, `gh pr checks` gives the conclusion and a URL but never the log; report the failure with that URL and ask a human to open it rather than spending turns on `gh run view`/`gh api .../logs` variations, all of which refuse the same way. #106 hit this the first time the `photos` pipeline ran for real.

Give a component built by a DOM module its own CSS class, never reusing a class name another `*-dom.ts` module already owns, even if the visual role looks similar — `BaseLayout.astro`'s global stylesheet has no scoping between them, so a margin/gap/padding rule written for one leaks straight into the other. #120's flash sheet reused home-dom.ts's `.restaurant-list` for its own scrolling row container and inherited that class's `margin`/`gap` unchanged, doubling its row spacing; every DOM test stayed green (they check the class/testid, not computed layout) and only `./scripts/app-render` showed the gap.

Size an inline icon shared across sites in `em`, not a fixed pixel value, and give it exactly one CSS margin as the only source of the gap to the text beside it — never a flex `gap` layered on top of a literal separator (" · ") already in that text, and never a literal leading space on top of the icon's own margin. A fixed px value renders fine next to one site's small muted text and reads as a speck next to another's large bold text; a second gap source on top of the margin reads as uneven spacing. Both pass every DOM test unchanged (they check for the element/class and `textContent`, not computed size or rendered whitespace) and only a real render shows either. #130's round 1 review caught both on the same icon: a speck beside the tracker's bold countdown, and doubled spacing on home cards and the restaurant page's flex `.restaurant-meta`.

When hand-drawing an inline icon's path data, spread the shape across most of the 0–24 `viewBox` in both axes rather than clustering it in the box's middle band — a shape confined to the middle third still reads as a blocky squiggle at the ~15px an icon this size actually renders at, no matter how large the surrounding 4× review crop looks. #130's round 1 redraw passed its own 4× crop and was rejected again in round 2 for exactly this; only path data that used nearly the full box (supplied by the driver directly, the second time round) read as a scooter and a car inline.

Toggling an element's native `hidden` property is not enough when that element's own class sets `display` to anything other than the default — the class's author-level rule (`display:flex`/`block`/`grid`) beats the browser's built-in `[hidden] { display: none }` at equal specificity, so a "hidden" element still reserves its box. Add an explicit `.the-class[hidden] { display: none }` rule alongside it. Two instances now: `.cart-badge[hidden]` (Header.astro, #67) and `.carousel-caption[hidden]` (#151, hiding the first-order slide's empty caption strip).

Give a grid or flex item `min-width: 0` when its content has to wrap or shrink to fit its track/basis, not just when it visibly needs to — a grid/flex item defaults to `min-width: auto` (its content's own min-content size), which wins over the track width and overflows into the next column/item instead of wrapping, even when the content carries its own break points (`<wbr>`). No DOM test catches this (they check text/class, not layout); only a real render does. #137's home-only header row put the wordmark, a `<wbr>`-broken span meant to wrap at 375px, in a grid's first `1fr` column without this, and it silently overflowed into the city pill's column — the render showed the pill's background painted over the missing word rather than any visible clipping. The same `min-width: 0` already fixes `.voucher-main`/`.confirm-button` elsewhere in this file's history.

When a wide-viewport mock goes to more than one column, check the mock's own `main` rule rather than assuming the sitewide `main { max-width: 40rem }` (global.css) still applies — that width is sized for one column, and a second column squeezed into what it leaves over wraps every long value a few characters per line while every DOM test stays green (they check text content, not layout). #148's wide Tracker (Live now capped at 25rem, Past orders filling the rest) reused the sitewide `main` unchanged; `./scripts/app-render` showed a restaurant name wrapping to one letter per line, and the fix was `main:has(#tracker-root) { max-width: 62rem }` inside the existing `@media (min-width: 481px)` block, matching the width the mock's own HTML already set.

Postgres grants `EXECUTE` on a new function to `PUBLIC` by default in every schema, not just `public` — a private helper never explicitly `revoke`d loses nothing to the Data API (which never exposes `private` at all), but is still directly callable by `anon`/`authenticated` through their `PUBLIC` membership if a test ever connects as them and calls it by name, and a catalog check for "no client-reachable function takes a time argument" is the only thing that catches it. #145's first draft left two `private.drip_*` helpers un-revoked; only a `has_function_privilege` sweep across every schema (not just `public`) caught it. Revoke execute from `public` on every private helper as it's created, the same way the public-facing functions strip their own default grants.

When a feature flag/config gate must keep an existing code path perfectly synchronous (its own tests call it with no `await`), gate the fallback with a variable checked *before* any `await` is reached, not by `await`ing a promise that merely resolves to the fallback value — `await` always defers to a microtask even when the awaited promise is already settled, so a `dark`/off path reached only through an `await somePromise()` breaks every caller that doesn't itself `await` the outer call. #149's checkout wallet gate stays fully synchronous when there's no config to probe (no `await` in that branch at all) and only actually awaits when a real network probe is in flight.

Give any element that holds a raw SVG icon (`el.innerHTML = ICON_CONSTANT`, this codebase's pattern for `CHECK_ICON`/`STAR_ICON`/etc.) an explicit `<its-own-class> svg { width: 100%; height: 100% }` rule, not just a sized wrapper — an inline `<svg>` renders at its own intrinsic size (whatever its `viewBox` implies, often 400px+) regardless of the parent element's own `width`/`height`, and no DOM test catches it since none lay out CSS. #169's 76px Delivered stamp rendered as a giant checkmark filling most of the card until this rule was added; only `./scripts/app-render` showed it.

In a DOM test, re-query an element from its root *after* any click that can trigger this codebase's own re-render (`root.innerHTML = ''` then rebuild, `tracker-dom.ts`/`checkout-dom.ts`'s own `render()` pattern) — a reference captured before that click is now detached, and a later `.click()` or `.querySelector` on it silently no-ops or returns stale content rather than throwing, which reads as the feature being broken when it's the test holding a dead node. Also recompute a "sticky" default (a pre-picked radio option, the first-affordable preset) once, the first render it's needed, rather than re-deriving it from live state on every render — otherwise a later, unrelated state change (a balance update) silently swaps out a selection the visitor already saw. #171's tip panel hit both: three failing tests traced to a stale row reference reused across a toggle-then-click, and the short-balance block never showing because the preset pick was being recomputed against the post-response balance instead of the one the visitor tapped against.

Start every `docs/design/shots/*-seed.js` with `/* global window, document */` - `eslint .` lints those files as Node, so a seed script that touches the page fails CI on `no-undef` (#177's six seeds), not just locally.

In a DOM test that reaches the rating sheet's win, stub `matchMedia` to `prefers-reduced-motion: reduce` (or mock `canvas-confetti`) - happy-dom's 2D context is `null`, so a real confetti frame fires after the test ends and fails the run with an unhandled error even though every test passes (#178).

Supabase grants `execute` on every new `public` function directly to `anon` and `authenticated` at creation time (its own project-level `alter default privileges`), not only through the `PUBLIC` pseudo-role — so `revoke all/execute ... from public` on a public-facing function strips `PUBLIC`'s own grant but never touches that direct grant, and PGlite has no Supabase project so a test never sees the hole unless it first runs that same `alter default privileges ... grant execute on functions to anon, authenticated` before applying the migrations. `wallet_get`/`wallet_claim_drip`/`wallet_debit`/`wallet_tip` shipped reachable by `anon` on the live database this way for two migrations running; #188 closed it with an explicit `revoke execute ... from anon` on each, next to the already-`authenticated`-only grant.

When splitting a DOM module's flex container into two elements (e.g. wrapping two sibling text spans in a new intermediate div for a layout change), give the new wrapper its own `display:flex; flex-direction:column` explicitly rather than assuming it inherits the removed parent's layout — a plain `<div>` defaults to block, but its inline-`<span>` children still sit on one line with no break between them, and no DOM test catches it since none lay out CSS. #184/#185's first-order banner wrapped `.carousel-slide-panel-claim`/`-sub` in a new `.carousel-slide-panel-copy` and the two ran together ("order Applied automatically…") until `./scripts/app-render` showed it.
